# shipcut: этапы

Все этапы обозначены здесь, но подробный PRD существует только у текущего.
PRD следующего этапа пишется после закрытия предыдущего, потому что результаты
меняют планы.

Текущий этап: 2. Запуск как open source (`docs/prd/02-launch.md`).
Этап 1 закрыт 2026-10-07, итог в `docs/prd/01-picture.md`.

## Как растет документация

- Один этап - один файл в `docs/prd/`, с номером.
- Закрытый PRD не редактируется. В его конец добавляется раздел "Итог": что
  сделано, что отброшено, какие цифры получились.
- Решения, которые переживают этап, переносятся в `PRODUCT.md` или
  `AGENTS.md`. PRD их источником не считается.
- Идеи вне текущего этапа складываются в "Заметки" внизу этого файла.

## 1. Картинка (закрыт 2026-10-07)

Цель: ролик выглядит так, что его хочется опубликовать.

Результат: 30 кадров/с в вертикальном формате, плавный указатель, зум на
действие, рамка и фон, аккуратные титры.

Готово, когда: выполнены критерии из PRD и есть три ролика Heystol, которые
Роман готов выложить без оговорок.

Вне рамок: CI, хранилище.

## 2. Запуск как open source

Цель: любой ставит `shipcut` одной командой и находит его по постам Романа.

Результат: пакет `shipcut` в npm, открытый репозиторий под MIT, лендинг
`shipcut.dev` с командой установки, посты о запуске в X, Threads, Show HN,
сообществе Playwright и на Indie Hackers.

Готово, когда: `npm install -g shipcut` ставит рабочий CLI на чистой
Linux-машине и посты опубликованы.

Этап начинался как проверка спроса для платного сервиса. 2026-10-11 Роман
решил, что платного продукта нет; этапы "Сервис" и "Детектор изменений и
оплата" и критерий остановки убраны.

## 3. GitHub Action

Цель: ролик пересобирается на CI-раннере пользователя одним шагом в workflow.

Результат: Action, который ставит ffmpeg и Chromium, прогоняет сценарии и
публикует результат в bucket пользователя.

Готово, когда: Action работает в чужом репозитории без помощи автора.

Открытые вопросы: как сценарий получает адрес preview-деплоя, как передавать
состояние входа в CI.

## Заметки

Сюда складываются идеи вне текущего этапа.

- Агент пишет черновик сценария по URL, человек его правит. Основной путь
  уже другой: сценарий пишет кодовый агент клиента по скиллу (`PRODUCT.md`,
  "Для кого"). Идея остается на потом.
- К этапу 3: скилл как интерфейс продукта. Пример сценария со входом,
  маской и главами, команда вроде `shipcut init`, которая кладет скилл и
  пример в репозиторий клиента.
- Озвучка глав синтезированным голосом.
- Экспорт GIF для README из того же прогона.

### Хвосты этапа 1

- К этапу 3: в Action нужен ffmpeg с librsvg; популярные статические сборки
  его не всегда включают.
- К этапу 3: страница без веб-шрифтов рисуется шрифтами раннера, эмодзи без
  цветного эмодзи-шрифта выходят квадратами. Noto Color Emoji около 10 МБ,
  его лучше ставить при установке Action, чем держать в репозитории.
- К этапу 3: покадровый рендер не работает на macOS. Мак-пользователю нужен
  CI или Linux в Docker.
- Desktop в 2x: `polish` доходит до 1363 МБ из лимита 1.5 ГБ этой машины.
  Если упремся, урезать потоки и lookahead x264 на больших кадрах.
- Подписи держатся вне безопасных зон `story` с запасом: зоны считаются для
  записи на весь экран, а окно в рамке меньше.

### Веб-интерфейс к своему хранилищу

Перенесено из плана от 2026-10-02, написанного до того, как этап 1 стал
первым. Это заготовка, не решение и не этап: просмотрщик своего bucket, не
сервис.

- Next.js с App Router в `web/` этого репозитория, серверные компоненты,
  один клиентский лист для кнопок копирования и подтверждения удаления.
  Деплой в проект Vercel `shipcut` с корнем `web`; хранилище к этому времени
  уже R2. Белое на черном, один sans, плотно.
- Без базы. Интерфейс читает Blob так же, как `shipcut list`: проекты из
  свернутого листинга корня, прогоны проекта из `currentIndex`, прогон из его
  `manifest.json`. Переименование переписывает манифест и запись индекса,
  удаление это `remove()`. Кэш `"use cache"` с тегом на проект и минутой
  жизни, действия вызывают `updateTag`. База появляется только с данными,
  которых нет в прогоне: заметки, теги, поиск по тысячам прогонов. Тогда Neon
  с Drizzle как индекс поверх Blob.
- `src/store.ts` сначала делится: функции данных (`listProjects`,
  `currentIndex`, `readManifest`, `publishRun`, `retitleRun`, `removeRun`)
  без печати и без вопросов, печать и подтверждение в `src/cli.ts`.
  Интерфейс импортирует из `../src/store.ts` и `../src/types.ts`. Проверить
  раньше страниц: что Next собирает импорты с `.ts` из-за пределов корня и
  что Vercel включает `../src` в сборку. Иначе pnpm workspace с `src/` как
  пакетом.
- Маршруты: `/` проекты с новыми прогонами, `/[project]` все прогоны,
  `/[project]/[run]` плеер, снимки, главы с таймкодами, коммит и ветка,
  размеры, копирование, переименование, удаление, `/login`.
- Доступ: стор публичный, а интерфейс умеет удалять, поэтому закрыт. Один
  секрет `SHIPCUT_SECRET`, `/login` сравнивает его за постоянное время и ставит
  `HttpOnly`, `Secure`, `SameSite=Lax` cookie с HMAC. `proxy.ts` отправляет
  запрос без cookie на `/login`, каждое серверное действие проверяет cookie
  само. Настоящий вход появляется со вторым человеком. Это расходится с
  "вход через GitHub" в описании этапа; решить при написании PRD 04.
- Готово, когда прогон из CLI виден за минуту, переименование и удаление
  видны в `shipcut list` сразу, каждый маршрут без cookie отдает вход или
  отказ, потолок индекса (одна страница листинга, 1000 прогонов) либо снят
  через `cursor`, либо помечен `ponytail:` в `store.ts`.
- Мелочь из того же плана, которая не дождалась: `publish` читает файл в
  память, для файлов больше 100 МБ нужен multipart upload.
