# PRD 02: запуск как open source

Перед началом прочитай `PRODUCT.md`, `ROADMAP.md` и `AGENTS.md`. Этап 1 закрыт
2026-10-07, его итог в `docs/prd/01-picture.md`.

Этот PRD начинался как проверка спроса: список ожидания, пороги сигналов и
решение "идем в сервис или нет". 2026-10-11 Роман решил, что платного
продукта у shipcut нет, и этап переписан в запуск открытого CLI. Что было
сделано до решения, осталось в "Итоге".

## Проблема

Платить за shipcut некому. Демо-ролики из кода уже делают бесплатные открытые
инструменты (AutoDemo, demowright, playwright-recast, argo), а те, кто платит
за демо, это маркетологи, и они платят Arcade и его соседям за редактор, а не
за сценарий в репозитории. Сервис со ссылками и плеером конкурирует с
бесплатным, а пивот в мониторинг с видео был бы новым продуктом: видео при
падении Checkly и другие уже дают, а движок shipcut закрывает малую часть
работы. Разбор лежит в заметках проекта: `notes/monetization.md`,
`notes/competitors-funnel.md`, `notes/monitoring-pivot.md`.

При этом инструмент работает и дает ролики, которые не стыдно выложить. Ему
нужен не бизнес-план, а нормальный выход в открытый доступ.

## Цель

`shipcut` стоит одной командой `npm install -g shipcut`, репозиторий открыт под
MIT, лендинг `shipcut.dev` говорит, что это и как поставить, а Роман
опубликовал посты о запуске. Дальше shipcut работает на репутацию и
портфолио Романа и снимает ролики для его продуктов, начиная с Heystol.

## Принятые решения

- **Платного сервиса нет.** Ни тарифов, ни оплаты, ни хостинга роликов, ни
  проверки готовности платить. PR #2 с ценами на лендинге закрыт 2026-10-11.
- **Спрос не меряется.** Нет порогов, окна, таблицы сигналов и решения
  "идем или стоп". Ответы на посты это разговор с пользователями, а не
  данные для решения.
- **Без дат.** Посты выходят, когда Роман готов, по одному, чтобы успевать
  отвечать. Этап закрывается, когда выполнены критерии приемки.
- **Установка из npm.** Пакет `shipcut` собирается в `dist/` и публикуется из
  PR #1. Посты и README ведут на `npm install -g shipcut`, сборка из клона
  остается для тех, кто правит код.
- **Посты говорят, что есть сегодня.** Открытый CLI: сценарий на TypeScript в
  репозитории, покадровый рендер на виртуальных часах, оформление поверх,
  публикация в свой bucket R2. Ничего "coming", никаких обещаний сервиса.
- **Публикует Роман со своих аккаунтов.** Агент пишет черновики в
  `docs/launch/posts.md`, Роман правит и постит. Агент ничего не публикует
  снаружи.
- **Ролики для постов уже есть**, это ролики Heystol из "Итога". Новых не
  пишем: Роман 2026-10-09 решил больше не вкладываться в ролики Heystol.

## Риски

- Пост почти никто не увидит. Это не ломает цель: открытый репозиторий и
  пакет в npm работают на портфолио и без охвата.
- Чужие запуски упрутся в окружение: ffmpeg без librsvg, macOS без
  покадровой записи, непроверенный Windows. README говорит об этом прямо, а
  вопросы из ответов идут в issues.
- Конкуренты бесплатны и похожи. Ответ в постах не "мы лучше", а чем именно
  отличается: покадровый рендер и оформление по журналу событий.

приложение для Shopify "ShipCut Shipping Discounts", скидки на доставку,
другая ниша. Команда CLI переименована в `shipcut` 2026-10-07, чтобы ставили

### Часы и запросы, 2026-10-08

Правка CLI по просьбе Романа. При `--frame-by-frame` любой `fetch()` страницы
держал часы 5 с, а потом до конца прогона время шло мимо запросов. Это
касалось и обычного GET, не только server action. Сервер отвечал за 0.3 с, но
ответ не доходил до страницы. Причина в кадре со снимком: после
`HeadlessExperimental.beginFrame` со `screenshot` Chromium не отдает странице
ответы сети до следующего BeginFrame, а следующий кадр ждет часы. Теперь
после каждого кадра `run` просит у Chromium второй, пустой, на 0.001 мс
позже, и ответы проходят.

| Проба, ответ сервера через 0.3 с         | До                                              | После                                                                                   |
| ---------------------------------------- | ----------------------------------------------- | --------------------------------------------------------------------------------------- |
| GET, POST, POST с chunked-ответом        | 5.5 с ожидания, часы отпущены до конца прогона  | 10 мс времени страницы, мгновенно                                                       |
| Поток, который страница читает по кускам | то же                                           | время страницы примерно равно длине потока; в 1 из 9 прогонов часы все же держались 5 с |
| Событие Heystol, три прогона             | часы держались на `POST /events`, форма пустела | 20.90, 20.83, 20.83 с, без удержания                                                    |
| `examples/motion.ts`, время записи       | 25.7 с                                          | 25.7 с                                                                                  |

За это `requestAnimationFrame` вызывается дважды за кадр. Анимация, которая
читает время, не меняется, а та, что считает вызовы, идет вдвое быстрее.
Счетчик `motion.ts` показывает 600 вместо 300. Пустые кадры только на время,
пока запрос держит часы, тоже пробовались. Такой кадр посреди бюджета в двух
прогонах Событий из четырех так и не завершился, и запись вставала. Остальные
ролики записаны до правки: часы держались 5 с на первом запросе, потом время
шло мимо запросов. В кадре этого не видно.

Сделано тремя агентами параллельно, проверено, не задеплоено.

### Хранилище и почта, 2026-10-08

Blob удален, файлы `shipcut publish` переезжают в Cloudflare R2. Роман
решил перенести DNS `shipcut.dev` в Cloudflare: только так R2 отдает файлы
со своего домена, `media.shipcut.dev`, а не с ограниченного `r2.dev`.
Лендинг остается на Vercel по CNAME. Там же, в Cloudflare, встанут записи
Resend для отправки с `hello@shipcut.dev` и маршрутизация входящей почты на
этот адрес. Это перенос раньше этапа 4: без хранилища у `publish` нет места
для роликов лендинга.

Проект Vercel был связан со старым `RomanDenysov/shots` и пуш не увидел.

Агент проверил в headless Chromium на desktop и phone: ролики играют из R2,
строка `step()` подсвечивается в такт ролику. Функция отвечает 400 на

не проверены.

### Лендинг на Next, 2026-10-09

Решение "одна статическая страница без фреймворка" отменено. Роман: продукт
будет полноценный, и лендинг должен стоять на том же стеке, что Heystol.
`web/` теперь приложение Next 16 с Tailwind и shadcn в стиле `base-vega`
(Base UI), пакет `@shipcut/web` в workspace pnpm. Линтер для всего репо
oxlint с пресетами Ultracite и `@shadcn/lint`, форматтер oxfmt. Правила,
которых код CLI пока не выполняет, выключены списком LATER со счетчиками в
`oxlint.config.ts`.

Дизайн по брифу Романа: черный фон, фиолетовый для действий, лавандовый и
голубой остаются токенами. Шрифт Satoshi из Fontshare: его лицензия
запрещает класть файл шрифта в публичный репозиторий, поэтому он грузится с
их API. В hero слева текст, справа карточка приложения, по которой ходит
указатель с волной клика и подписью шага, как в ролике shipcut. Ниже три
преимущества и изометрическая доска процесса: Push, Record, Polish, Publish.
Push помечен "coming". Список ожидания открывается в диалоге и стал server
action. Ролики Heystol на лендинге больше не показываются.
